# Glossary

Every term, alphabetical, with the lesson that teaches it. Filled in as lessons are built.
- **acceptance rate** — the share of draft-proposed tokens that the target model keeps; it sets how many tokens one verify pass yields (lesson 17)
- **activations** — scratch memory a GPU uses for one forward step; it peaks during a long prefill and is not in the model config (lesson 05)
- **admission control** — the engine or gateway refuses a request at the door, with HTTP 503, when a queue limit is reached, instead of letting it wait (lesson 33)
- **all-reduce** — a step where every GPU in a group adds its partial result to the others' and gets the total back; tensor parallelism runs one after each layer (lesson 19)
- **allowlist (proxy)** — a rule in front of an engine that forwards only the paths you name and blocks the rest, so utility and control paths are not public (lesson 36)
- **arithmetic intensity** — FLOPs a step does divided by bytes it reads from memory; it says which limit (maths or memory) the step hits (lesson 06)
- **attention** — the step where each token compares itself with the earlier tokens to decide what to take from them; its work grows with the square of the prompt length in prefill (lesson 02)
- **audit trail** — a record of who called which model version, when, and with how many tokens, kept without the prompt text (lesson 36)
- **autoregressive decoding** — generating a reply one token at a time, each new token depending on all the tokens before it (lesson 02)
- **AWQ** — 4-bit weight quantization that uses activation statistics from calibration samples to protect the most-used weight channels; needs sample text (lesson 20)
- **backpressure** — the wait that builds when a receiver reads more slowly than the sender writes; in streaming, bytes queue in network buffers until the client reads them, and the sender is held back (lesson 08)
- **block (KV block)** — a fixed-size group of token slots in the KV cache, 16 tokens by default in vLLM; requests take blocks as their tokens arrive (lesson 10)
- **block table** — the ordered list of block ids that holds one request's KV cache; token i sits at `table[i // block size]`, offset `i % block size` (lesson 11)
- **breakeven** — the point where two options cost the same, for example the share of hours a GPU must run for a reserved commitment to beat on-demand (lesson 28)
- **build vs buy** — running your own model servers against paying an API per token, compared per served token at the utilisation you can hold (lesson 28)
- **cache hit rate (prefix)** — the share of prompt tokens served from the prefix cache, so the GPU skips their prefill (lesson 28)
- **cache_salt** — a request field mixed into the first block's hash, so only requests with the same salt share prefix-cache blocks; not an isolation boundary (lesson 36)
- **calibration data** — sample texts run through a model before quantizing, so the method can measure activations and choose better rounding; AWQ and GPTQ need it, data-free schemes do not (lesson 20)
- **canary release** — sending a small share of traffic to a new version first, and widening that share only while a guard reports no harm (lesson 35)
- **capacity report** — a one-page record of a concurrency estimate (arithmetic), a measured p95 TTFT (a real server), the target and the verdict, with the basis of each number (lesson 09)
- **causal attention** — attention in which a token can look at itself and earlier tokens only, never later ones (lesson 02)
- **chunked prefill** — splitting a long prompt's prefill over several steps so that each step stays within the token budget and decoders keep their token rhythm; it lowers the ITL tail and raises the TTFT of the long prompt (lesson 12)
- **closed-loop test** — each simulated user waits for an answer before asking again, so a slow server slows the test and hides its queue (lesson 27)
- **cold start** — the delay before a new replica can serve: loading weights and warming the engine; the ready check on the CPU image took about 4 minutes (lesson 31)
- **compute-bound** — a step whose time is set by how fast the chip does arithmetic; prefill is compute-bound (lesson 06)
- **continuous batching** — admitting a request into the running batch on any step and freeing its slot when it finishes, instead of waiting for the whole batch to drain; also called in-flight batching (lesson 12)
- **cooldown** — after a failure, a gateway stops sending calls to that replica for a set time (lesson 29)
- **cost per million tokens** — the hourly price of a GPU divided by the tokens it serves in that hour, times a million (lesson 28)
- **data-free quantization** — rounding the weights from the model file alone, with no sample text (for example W8A16, FP8_DYNAMIC, W4A16 in llm-compressor) (lesson 20)
- **decode** — the phase where the model writes one new token per step, reading the weights and the cached tokens each time (lesson 01)
- **degraded mode** — serving at lower capacity after a failure, refusing the excess early instead of queueing it (lesson 40)
- **dense FLOP/s** — a GPU's peak maths speed without structured sparsity; NVIDIA's pages quote sparse, which is about twice the dense figure (lesson 24)
- **dequantize** — multiply stored small integers by their scale to get back the number used in a matrix product (lesson 20)
- **disaggregated serving (prefill/decode disaggregation, P/D)** — running prefill and decode on separate GPU pools; the prompt's KV cache moves from the prefill pool to the decode pool once per request (lesson 34)
- **draft model** — a small proposer that guesses the next tokens for the target model to check (lesson 17)
- **draft-and-verify** — speculative decoding's loop: a cheap proposer guesses k tokens, the target checks all k in one forward pass (lesson 17)
- **drained queue** — after a failure drill, no requests running or waiting on any replica; `vllm:num_requests_running` and `vllm:num_requests_waiting` are back at 0 (lesson 37)
- **EAGLE** — a speculative-decoding proposer that is a small head built on the target model's hidden states (lesson 17)
- **Erlang C** — the formula giving the chance that an arrival must wait in an M/M/c queue (lesson 26)
- **Erlangs (offered load)** — the average number of busy slots if no request waited: arrival rate × service time (lesson 26)
- **error budget** — the highest error rate a change may cause; a gate reads the confidence bound of the measured rate against it, not the point value (lesson 35)
- **error budget policy** — the written rules for an exhausted budget: authors, approvers, review dates, actions and escalation (lesson 39)
- **eval gate** — a fixed set of cases run on a candidate before any user sees it; the candidate must pass its error budget and its agreement rule to move on (lesson 35)
- **expert parallelism (EP)** — placing the experts of a mixture-of-experts model on different GPUs, so each token is sent only to the GPUs that hold its chosen experts; vLLM turns it on with `--enable-expert-parallel` (lesson 23)
- **extended resource (nvidia.com/gpu)** — a resource a device plugin advertises to the scheduler; a pod asks for GPUs with a limit on it (lesson 32)
- **fail-back** — moving traffic back to a region or replica after it recovers; it needs its own drill, because it is not always clean (lesson 40)
- **failure domain** — a set of parts that fail together: one engine, one node, one zone, one region, or one service such as the gateway database; each has its own RPO and RTO (lesson 38)
- **FP8 KV cache** — the KV cache stored with 1 byte per value (FP8 e4m3 in vLLM's `--kv-cache-dtype fp8`), so the same memory holds twice the tokens; the rounding can change answers (lesson 21)
- **FP8 tensor cores** — hardware that runs FP8 maths fast; present on the L4, H100 and H200, not on the A100 (lesson 24)
- **free list** — the pool's list of blocks that no request holds; a request takes one when its last block is full, and finishing returns them (lesson 11)
- **gate** — a pass rule written before a change or a drill, with numbers that decide PASS or FAIL; the eval gate of lesson 35 and the recovery gate of lesson 37 (lesson 37)
- **gateway** — the one endpoint in front of several replicas: it holds the replica list, routes each request, retries failed calls and cools down a failing replica (lesson 29)
- **GGUF** — the single-file model format llama.cpp and Ollama load, with weights quantized for CPU and laptop GPUs (lesson 15)
- **golden output** — the answer tokens a reference setting (here FP16 KV) produces for a fixed prompt, saved so later runs can be compared with it (lesson 21)
- **goodput** — requests per second that meet every latency SLO target (for example TTFT and TPOT); unlike throughput, a fast request that misses its target does not count (lesson 07)
- **GPTQ** — 4-bit weight quantization that rounds weights one column at a time with second-order information from calibration samples (lesson 20)
- **gpu_memory_utilization** — the vLLM setting for the share of GPU memory one engine may use (default 0.92 on main); weights, activations and KV cache all fit inside it (lesson 05)
- **GQA (grouped-query attention)** — several query heads share one KV head, so the cache stores fewer key and value vectors per token (lesson 03)
- **graceful drain** — stopping new requests to a replica, letting its in-flight requests finish, and only then stopping it (lesson 35)
- **group (serving group)** — the set of GPUs that serve one copy of the model; its size is the tensor-parallel degree (lesson 23)
- **hash chain** — each block's hash covers its tokens and the hash of the block before it, so a block matches only when its whole prefix matches (lesson 14).
- **HBM and GDDR** — the GPU's own large memory that holds the weights and the KV cache; HBM on data-centre cards, GDDR on the L4 (lesson 24)
- **headroom** — spare capacity kept above the peak load (here 30%), so bursts and one failed replica do not cause misses (lesson 25)
- **Helm chart** — a package of Kubernetes manifests with values that set the settings per environment; vLLM's docs have a chart for its server (lesson 32)
- **hit rate (prefix cache)** — prompt tokens found in the cache divided by prompt tokens queried; in vLLM, the change in `prefix_cache_hits_total` over the change in `prefix_cache_queries_total` (lesson 14).
- **HPA (Horizontal Pod Autoscaler)** — the Kubernetes controller that sets a replica count from metrics: desired = ceil(current × value / target), the largest over its metrics (lesson 31)
- **image pinning** — running a container image at a fixed tag (here `vllm/vllm-openai-cpu:v0.32.0`), never `latest`, so the same bytes run everywhere (lesson 32)
- **INT4 / INT8** — integer weight formats with 4 or 8 bits per number; the group scales add a little overhead (lesson 20)
- **internal fragmentation** — memory that is reserved but not used, inside a unit handed to one request, such as the empty tail of a max-length reservation (lesson 10)
- **ITL (inter-token latency)** — the gap between two consecutive streamed tokens; TPOT is the mean ITL after the first token, and the ITL tail shows stalls (lesson 07)
- **KEDA** — Kubernetes Event-driven Autoscaling; scales on an external source such as a Prometheus query (lesson 31)
- **keyed hash (HMAC)** — a hash that needs a secret key to recompute, so a log reader cannot test guesses against it (lesson 36)
- **knee (utilisation knee)** — the utilisation above which waits climb steeply (lesson 26)
- **kubeconform** — a single binary that checks Kubernetes objects against the API schema, strict mode rejects unknown fields; it runs offline with local schemas and no cluster (lesson 32)
- **KubeRay** — the Ray project's Kubernetes operator; vLLM's Kubernetes docs list it for serving across several nodes (lesson 32)
- **KV budget** — GPU memory allowed by utilisation, minus weights and activations; what is left holds the KV cache (lesson 05)
- **KV cache** — the stored keys and values of earlier tokens, so they are not recomputed; it holds GPU memory until the request ends (lesson 01)
- **KV head** — a head whose keys and values the cache stores; its count is `num_key_value_heads` in `config.json` (lesson 03)
- **KV offload** — copying KV blocks out of GPU memory to CPU RAM or a shared store, so a paused or idle request can be restored instead of recomputed; vLLM setting `--kv-offloading-size` (GiB) and `--kv-offloading-backend native|lmcache` (lesson 13)
- **KV transfer** — moving a request's KV cache over the network from the worker that built it to the worker that decodes (lesson 34)
- **kv_cache_memory_bytes** — the vLLM flag that sets the KV cache size in bytes, overriding the share from gpu_memory_utilization; the CPU image uses it (lesson 16)
- **LeaderWorkerSet** — a Kubernetes API (kubernetes-sigs/lws) for a group of pods that starts and is replaced as one unit: a leader and its workers; the shape a model split across hosts needs (lesson 32)
- **least-busy routing** — send each request to the replica with the fewest calls in flight at the gateway (lesson 29)
- **length distribution** — the spread of prompt and answer lengths in a load test; a fixed length hides the long tail (lesson 27)
- **liveness probe** — a check the platform repeats to decide whether to restart a container that has stopped answering; a liveness check that starts too early restarts a server that is still loading (lesson 32)
- **LMCache** — an open-source KV cache layer for vLLM and SGLang with tiers from CPU RAM to local SSD, Redis or Valkey, Mooncake and S3-compatible storage (lesson 13)
- **load generator** — the client tool that sends traffic at a set rate and records latency (lesson 27)
- **LoRA adapter** — a low-rank correction (two small matrices per adapted layer) added to a shared base model; rank r is small, so an adapter is megabytes against gigabytes for the base (lesson 17)
- **M/M/c** — a queue with c servers, Poisson arrivals and exponential service times (lesson 26)
- **max concurrency** — how many requests can run at once: the KV budget divided by tokens per request times KV bytes per token, capped by `max_num_seqs` (lesson 05)
- **max-length reservation** — giving each request the longest slot it could ever need before it starts; simple, but most of the memory sits empty (lesson 10)
- **max_model_len** — the longest request, prompt plus output, that a vLLM server accepts; set with `--max-model-len`; a longer request gets a 400 error (lesson 16)
- **max_num_seqs** — the vLLM cap on sequences per scheduler step (default 128 on main); a second limit next to memory (lesson 05)
- **MBU (model bandwidth utilisation)** — bytes a decode step reads, divided by its time, divided by the GPU's peak bandwidth (lesson 06)
- **memory bandwidth** — bytes per second the GPU can read from its memory; for decode it sets the time per token floor (lesson 24)
- **memory-bound** — a step limited by how fast data can be read from memory, not by arithmetic; single-request decode is memory-bound (lesson 01)
- **MHA (multi-head attention)** — every query head has its own key and value heads; the biggest cache (lesson 04)
- **MLA (multi-head latent attention)** — the cache stores one compressed latent per token per layer and rebuilds the heads when attending (lesson 04)
- **MoE (mixture of experts)** — a model whose layers hold several expert networks and a router that sends each token to a few of them; total parameters set memory, active parameters set the bytes read per token (lesson 23)
- **Mooncake** — a KV-cache-centric store that pools CPU, DRAM and SSD across machines, behind Kimi's serving system (lesson 13)
- **MQA (multi-query attention)** — all query heads share one key head and one value head; the smallest cache, with a quality cost (lesson 04)
- **multi-LoRA serving** — one engine keeps one base model loaded and serves many LoRA adapters, chosen per request by the `model` field (lesson 17)
- **n-gram speculation** — a speculative proposer with no model: it copies the tokens that followed the last matching n-gram in the prompt or output (lesson 17)
- **NCCL** — NVIDIA's communication library that runs the GPU-to-GPU all-reduce and other collectives for multi-GPU inference and training (lesson 22).
- **node loss** — a replica or node stops answering in the middle of traffic; its share of the load moves to the survivors, which may start to refuse (lesson 33, checked in lesson 37)
- **nodeSelector** — a label match in a pod spec that limits the nodes a pod may run on; for GPUs it names the GPU type, such as `nvidia-l4` on GKE (lesson 32)
- **NVLink** — NVIDIA's direct GPU-to-GPU link; H100 NVLink is 900 GB/s for both directions together (lesson 22)
- **on-demand** — a cloud GPU billed by the hour while it runs, with no commitment (lesson 28)
- **on-prem** — a GPU you own and run in your own data centre; its cost is hardware, power and hosting, paid every hour (lesson 28)
- **open-loop test** — requests arrive on their own clock, for example with Poisson gaps, whatever the server's speed (lesson 27)
- **OpenAI-compatible API** — the HTTP paths and JSON shapes of the OpenAI API (for example `/v1/chat/completions`), which many engines serve so one client works with all of them (lesson 15)
- **option A and option B (regional sizing)** — full peak in each region, or half peak per region with a degraded mode after a region loss (lesson 40)
- **p50 / p95 (percentile)** — the value that 50% or 95% of requests stay under; p95 is the slow tail users notice (lesson 07)
- **PagedAttention** — vLLM's method of storing the KV cache in blocks with a block table per request, so memory is handed out as tokens arrive (lesson 10)
- **PCIe** — the bus that connects a GPU to the host; L4 uses PCIe Gen4 x16, about 32 GB/s in each direction (lesson 22)
- **pipeline parallelism (PP)** — splitting the model into stages of consecutive layers on different GPU groups; one token visits the stages in turn, so a single request is not faster, but all-reduces stay inside each stage (lesson 23)
- **PodDisruptionBudget** — a Kubernetes object that limits how many replicas a voluntary action (a node drain) may take down at once; `minAvailable: 1` keeps the last replica (lesson 32)
- **Poisson arrivals** — requests arriving at random gaps around a steady average rate (lesson 26)
- **preemption** — pausing a running request when the KV pool is full, freeing its blocks and putting it back in the waiting queue (lesson 13)
- **prefill** — the phase where the whole prompt goes through the model in one parallel pass and fills the KV cache (lesson 01)
- **prefill share** — the share of a GPU's time spent on prefill, which a prefix cache can skip (lesson 28)
- **prefix cache** — KV blocks kept under their hash, so a later request with the same leading tokens reuses them instead of recomputing (lesson 14).
- **prefix-aware routing** — send each request to the replica that already holds its leading prompt blocks, unless that replica is busy (lesson 30).
- **query-key pair** — one comparison between a token's query and one earlier token's key; counting pairs counts attention work (lesson 02)
- **queue depth** — requests waiting for a free slot in the engine (`vllm:num_requests_waiting`), the signal to scale on (lesson 31)
- **queue limit** — the most requests the engine holds at once (running plus waiting), set by `--max-num-queued-reqs` in vLLM; a request over it is refused and counted in `vllm:admission_rejections_total` (lesson 33)
- **radix tree** — a tree that stores shared prefixes once as paths of nodes; SGLang's RadixAttention uses one for exact-prefix KV reuse (lesson 14).
- **readiness probe** — a check that says whether a replica may receive traffic; for vLLM it is `/health` answering 200 after the weights load (lesson 32)
- **recompute (preemption)** — V1's way to resume a preempted request: its context is prefilled again when it is admitted, instead of being copied back (lesson 13)
- **regression set** — a fixed list of prompts with saved reference outputs, run after every change to catch quality loss; a tripwire, not proof (lesson 21)
- **replica** — one full copy of a serving group (for example 4 GPUs at TP=4) behind a load balancer; replicas add requests per second, and the group size sets memory (lesson 23)
- **reserved** — a cloud GPU committed for a term at a lower hourly rate, paid every hour whether used or not (lesson 28)
- **ridge point** — a GPU's peak FLOP/s divided by its memory bandwidth; steps above it are compute-bound, steps below it memory-bound (lesson 06)
- **rollback by weight** — moving traffic back to the stable pool by changing the router's weights, without restarting any pool (lesson 35)
- **roofline model** — a step's time is at least the larger of FLOPs divided by peak FLOP/s and bytes divided by bandwidth (lesson 06)
- **round-robin routing** — send each request to the next replica in turn; it ignores the prompt cache and the load (lesson 30).
- **RPO (recovery point objective)** — the data or work you can lose, counted back in time; zero means nothing stored is lost, not that the service stays up (lesson 38)
- **RTO (recovery time objective)** — how long a service is down before it serves again; set per failure domain (lesson 38)
- **scale (quantization)** — the number stored for each group of weights that maps the small integers back to real values (lesson 20)
- **scale-down window** — the time a scaler waits, using the largest recent desire, before it removes a replica; the HPA default is 300 s (lesson 31)
- **scheduling policy** — the rule that orders waiting and running requests: `fcfs` (arrival order) or `priority` (lower value first, then arrival) (lesson 13)
- **served token** — one input or output token processed by the server; the unit for cost per token here (lesson 28)
- **server-sent events (SSE)** — one long HTTP response in which the server writes a `data:` line per event; OpenAI-style token streams send one JSON chunk per token and end with `data: [DONE]` (lesson 08)
- **serverless GPU** — a container that runs on a GPU only while it serves requests (for example Cloud Run with one L4 per instance); idle instances scale to zero, and minimum instances are billed while idle (lesson 32)
- **session affinity (sticky routing)** — sending every request of one session to the same endpoint so its cached prefix is reused (lesson 39)
- **shadow index (router)** — the block hashes a router has sent to each replica, an approximation of that replica's prefix cache (lesson 30).
- **shard** — one equal slice of a model's weights (or cache) placed on one GPU (lesson 19)
- **simulated replica** — a stand-in server that takes time like a model but runs no model; used to show routing, never to show answers (lesson 29)
- **SLI (service level indicator)** — a measured ratio, good events over total events, such as the share of requests with TTFT under a threshold (lesson 39)
- **SLO (service level objective)** — the target a service is measured against, such as TTFT under 0.5 s; goodput counts requests that meet it (lesson 07)
- **sojourn** — the total time a request spends in the system, queue wait plus service (lesson 26)
- **speculative decoding** — generating faster by proposing several tokens and verifying them in one target-model pass, keeping the target's output distribution (lesson 17)
- **spot** — a cloud GPU at a lower hourly price that the provider can reclaim, so work may be lost and must be retried (lesson 28)
- **startup probe** — a check that holds off the liveness and readiness checks until the server has started; it lets a slow weight load take minutes without a restart (lesson 32)
- **swap (KV)** — the older way to pause a request: copy its KV blocks to CPU memory and back over PCIe; V1 does not use it by default (lesson 13)
- **taint and toleration** — a taint keeps pods off a node unless the pod tolerates it; GKE taints GPU nodes with `nvidia.com/gpu=present:NoSchedule` (lesson 32)
- **tenant** — one customer or team that shares a server and must not see another's data or timing (lesson 36)
- **tenant ceiling** — the most requests per second one tenant may send, here its share plus 20% (lesson 40)
- **tensor parallelism (TP)** — splitting each weight matrix across GPUs so they compute one forward step together; the degree must divide the head counts (lesson 19)
- **TensorRT-LLM** — NVIDIA's engine that compiles a model into an optimized engine for one GPU type and fixed settings; fastest on a fixed model, with a build step (lesson 15)
- **terminationGracePeriodSeconds** — how long a pod gets after a stop signal to finish in-flight work before it is killed; set it above the longest generation (lesson 32)
- **TGI (Text Generation Inference)** — Hugging Face's LLM server; in maintenance mode since 2026, so new deployments use vLLM or SGLang (lesson 15)
- **timing side channel** — information leaked by how long an answer takes; here, a faster first token after a prefix-cache hit (lesson 36)
- **token budget (max_num_batched_tokens)** — the number of tokens one engine step may process, decoders first, then prefill; vLLM's class default is 2048 (lesson 12)
- **token-budget routing** — send each request to the replica with the fewest estimated tokens in flight, prompt plus max_tokens (lesson 30).
- **TPOT (time per output token)** — the average time between generated tokens after the first (lesson 01)
- **TTFT (time to first token)** — the time from request to the first generated token, which ends the prefill (lesson 01)
- **utilisation (cost sense)** — the share of a GPU's capacity in use over an hour; cost per token rises as it falls (lesson 28)
- **warm-up run** — requests sent before the measured runs, so first-time engine costs do not reach the numbers (lesson 27)
- **weights (memory)** — parameters times bytes per parameter; fixed once the model is loaded (lesson 05)
- **Wilson interval** — a 95% range for a pass rate that stays inside 0 to 100% at the extremes; with 50 prompts it is about ±13 points (lesson 21)
- **zone-proof plan** — GPUs sized so that losing one zone leaves the survivors at or below the target utilisation: planned × zones ÷ (zones − 1) at three zones (lesson 38)
